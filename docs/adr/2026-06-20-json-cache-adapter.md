# JSON Cache adapter lifecycle and persistence

The Cache context adds a `JsonCache` adapter for local file-backed cache persistence while keeping Redis as the shared production cache backend. `JsonCache` reuses the in-memory cache store, loads strictly and idempotently during the Instance start hook using a compiled Valleyed JSON pipe, rejects `get`/`set`/`delete` before startup, persists absolute expiry timestamps, and writes eagerly with per-process queued atomic renames after mutations and expiry cleanup, including expired entries discovered by `get`. Load validation rejects malformed JSON and wrong known-field types while stripping unknown extras for forward compatibility. Any failed foreground cleanup or mutation write rejects the cache operation; a failed background expiry-sweep write crashes the Instance because there is no caller promise to reject. The adapter intentionally does not coordinate writes across processes because it is a single-process/local persistence option, not a shared cache backend.
